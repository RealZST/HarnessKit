HarnessKit supports {AGENT_COUNT} agents. This page lists where each one keeps its skills, MCP servers, hooks and rules, and what HarnessKit does when you turn one of them off. The tables are built from the site's data, which mirrors HarnessKit's adapter code, one file per agent.

## All agents

Paths that start with `~/` are in your home folder, which on Windows is `C:\Users\<name>\`. Paths that start with `<project>/` are inside a project. A path that ends in `/` is a folder. When an agent has more than one skill folder, HarnessKit installs into the first one listed. Hermes puts each skill in a category folder instead, as its section explains. The paths are the defaults. Where an environment variable moves them, the agent's section says so.

:::note[An agent in another folder]
If an agent is installed somewhere else, change its path in **Settings → Agent Paths**. HarnessKit then detects and scans the agent there.

The desktop app doesn't read environment variables set in your shell. The variables named in the sections below take effect only for `hk` and `hk serve` started from a terminal. In the desktop app, set the path in **Settings → Agent Paths** instead.
:::

HarnessKit counts an agent as installed when its home folder, listed below, exists. Devin Desktop also counts when `~/.devin/extensions/` exists, and Pi counts only when `~/.pi/agent/` exists. A folder that another tool created can make an agent look installed.

Some skill folders are shared. Several agents read `~/.agents/skills/`, and each agent's section says whether it does. `<project>/.agents/skills/` is shared too: HarnessKit lists it under Codex, Antigravity, Qoder CN and Pi, and Gemini CLI, Copilot, Grok Build and DeepSeek Harness also load skills from it. Turning off or deleting a skill in a shared folder affects every agent that reads it.

This page doesn't cover plugins. [Extensions](/docs/guides/extensions/) shows which agents have them, and what HarnessKit does to turn one off.

Each agent's section below lists its MCP, hook and rules files and their formats. Hook formats are named after the agent whose file layout they use, so "Claude Code JSON" also appears for other agents.

For every agent except Hermes, turning a skill off renames its `SKILL.md` to `SKILL.md.disabled`, or a single-file skill's `<name>.md` to `<name>.md.disabled`. For Hermes, HarnessKit adds the skill's name to `skills.disabled` in `~/.hermes/config.yaml`. For MCP servers and hooks, HarnessKit uses the agent's own off switch when it has one. Otherwise it removes the entry from the agent's file and keeps a [snapshot](/docs/how-it-works/installing-an-mcp-server/#enable-and-disable), an exact copy, in its database.

## Under the hood

- `crates/hk-core/src/adapter/` has one file per agent, with every path on this page.
- `crates/hk-core/src/adapter/mod.rs` defines the adapter trait, the config formats and the defaults each agent's file overrides.
- `crates/hk-core/src/manager.rs` turns skills, MCP servers and hooks off and on, natively, by renaming, or by remove and snapshot.
- `src/lib/types.ts` holds `AGENT_ORDER`, the order agents appear in across the app and this page.
- `website/src/data/agent-reference.ts` holds this page's data. Its test compares the data with the adapters' Rust tests: which agents have hooks, a project MCP file and a project hook file, each agent's first project skill folder, and which agents have their own MCP or skill off switch. It also checks that every environment variable an adapter reads is named in that agent's notes.
