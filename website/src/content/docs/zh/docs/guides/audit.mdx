HarnessKit 会检查每个扩展是否存在风险项，例如危险的 shell 命令、以明文保存的 API key，并给出 0 到 100 的**信任评分**。在**审计**页面展开扩展所在的行，即可查看扣分原因。

评分基于 HarnessKit 内置的 {AUDIT_RULE_COUNT} 项安全检查（静态分析规则），分为三档：**安全**（80 分及以上）、**低风险**（60–79 分）和**需复核**（低于 60 分）。这些检查自动执行，不能替代专业的安全审查。

## 运行审计

在**审计**页面点击**运行审计**，或点击**概览**快捷操作中的**运行审计**。在终端中运行 `hk audit` 会执行同一套审计，见 [hk 命令参考](/zh/docs/reference/cli/#hk-audit)。审计完成后，**审计**页面会显示已扫描的扩展数量和上次审计的时间。

审计只在手动运行时执行，重新扫描不会触发审计。此外，从市场、Git URL 或本地文件夹安装一个 skill 后，HarnessKit 会立即审计该 skill。其他新出现的扩展在**扩展**表格的**审计**列中显示 `--`；文件有改动的扩展保留原有评分。两者都要到下次**运行审计**后才会更新。

## 评分规则

每个扩展的初始分为 100 分。每条规则首次命中时，按严重程度扣分：

| 严重程度 | 扣分 |
|---|---|
| 严重 | 25 |
| 高 | 15 |
| 中 | 8 |
| 低 | 3 |

同一条规则再次命中时，每次只扣 1 分。最低分为 0。各条规则的检查内容见[安全审计的评分方式](/zh/docs/how-it-works/audit/)。

## 审计发现

**审计**页面按当前范围列出扩展，每个扩展占一行，评分低的排在前面。可以按名称搜索，或在**全部信任等级**中按档位筛选。扩展详情面板中的**查看审计**会打开**审计**页面并定位到该行。

- **无问题**。没有任何发现的扩展只显示一个简短的行，标有**无问题**。
- **有发现**。其他行会显示发现的数量。展开后列出每条未通过的规则及其严重程度。点击某条规则，可以查看它检查的内容以及每项发现的位置。
- **全部规则**。**显示全部 N 条规则**会同时列出已通过的规则，N 为适用于该类扩展的规则数。**仅显示失败项**会再次隐藏已通过的规则。**查看扩展**会打开该扩展的详情面板。

skill 正文或 plugin 脚本中的发现会给出行号。其他发现只注明文件、文件夹或扩展本身，例如 MCP server 的名称。

## 多个 agent 上的副本

HarnessKit 会分别审计每个 agent 上的副本。不同文件夹中的副本可能已经各不相同，一个 agent 上的副本安全，并不代表另一个 agent 上的副本也安全。多个 agent 读取同一个文件夹时，例如 `~/.agents/skills/`，它们读取的是同一批文件，审计结果也相同。

**扩展**表格和**审计**页面显示的是各副本中的最低分。在**审计**页面展开该行，会列出所有副本的审计发现。

## 权限

每个扩展的权限分为五组：**文件系统**、**网络**、**Shell**、**数据库**和**环境变量**。它们显示在**权限**列和详情面板中。

这些权限由 HarnessKit 根据可读取的内容推断得出，例如 MCP server 的启动命令或 skill 的正文。例如，以 `npx` 或 `uvx` 启动的 MCP server 一律标记为可访问任意网络域名（`*`），因为它运行的包可能会联网。该列表仅反映 HarnessKit 检测到的内容，并不构成限制。扩展实际能访问的资源可能多于列表所示。
